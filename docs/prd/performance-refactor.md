# 接管助手前后端精简与性能重构

日期：2026-11-12。来源：用户要求重构截图中的 Corsair 内存接管助手，使用慢、界面简陋，代码与体积尽量精简；前端先出方案，后端独立推进。

## 问题与目标
面向现有 Windows 用户，改善启动、重新检测与浏览检测结果的体验。当前公开源码 v0.3.1 使用 .NET Framework 4.8 / WinForms，无 NuGet；Probe.Scan 串行查询 WMI、注册表、任务与日志。用户提供的是 0.3 截图。耗时根因和改善幅度须实测，不能仅凭截图推断。

## 具体交付
1. 三张独立首页设计预览，基于原有概览、详情、帮助功能，减少大面积空卡与重复文字。用户选定前不更换正式视觉布局。
2. 保持原生轻量依赖的采集后端重构：依据测量去除重复或无关工作，保持每次检测可信，必要时修正影响响应的调用结构。
3. 本地可构建候选程序、相关源码与有意义的回归测试；记录旧/新同环境检测耗时和产物字节数。

## 2026-11-12 用户选择与范围修订
- 用户明确选方案 3，视觉目标为本轮第三张图 dist/design/option-3.png：浅色原生窗口、精简顶栏、左侧状态/设备行/检测操作，右侧接入步骤。使用真实检测状态驱动内容，保留详情、品牌帮助、导出、适用品牌维护与撤销；不照抄参考图的成功假数据。
- 用户明确慢在“连接内存或者执行连接操作时”。此前扫描提速不能代表该问题已解决。新增核对 v0.3 旧版与 v0.3.1 当前操作入口、服务等待和重复验证，去除有证据的无效开销；保留必要的安全重验与服务等待契约。
- 本轮实现选定前端，界面采用原生 WinForms，不按网页模板另建壳。参考图仅用作布局，生产程序不内嵌整张大图。适应常规窗口与 DPI，长中文不裁切，操作期间能解释当前等待。
- 验证：实际控件离屏渲染与选图对照；导航、帮助、不同检测状态与忙态使用合成数据检查，故障不得显示为成功。后台/维护链只做只读诊断与模拟用例；不主动操作真实内存服务、重启驱动或触发提权。
- 针对性审查：技嘉旧版可能运行过服务重启流程，但当前 v0.3.1 已取消其自动恢复。不能为展示“连接加速”重新开放该旧功能，不能跳过签名/指纹校验，不能把官方软件或硬件完成时间算成本工具扫描耗时。若入口仍不明确，询问最少的按钮/时长信息，同时推进前端。
- 运行时模型请求仍为正常/重试/回退各 0 次，无新增依赖。先实现 UI 与诊断连接链，再集中构建、相关回归、离屏多状态预览，打包本地候选；不重复未受影响的采集性能对照。

## 成功标准
### 2026-11-12 后续明确授权：连接、图标和退出设置
- 用户已选择“保留连接功能并优化等待”，替代上文暂不恢复 GIGABYTE 操作的限制。恢复手动的一次性连接入口，使用当前进程/服务及连接日志证据、有上限的轮询代替固定 20/18 秒等待；不恢复旧版持久驱动禁用、开机设置改写或技嘉自动维护。
- 用户要求应用/任务栏图标、设置可隐藏任务栏入口，以及降低占用或连接成功后静默退出。增加一套小尺寸可辨认的内存与连接符号图标，嵌入 EXE 并用于窗体/托盘；原生设置页保存两个布尔选项，隐藏任务栏时保留托盘打开与退出入口。
- 默认保留任务栏；默认在用户主动执行连接且重新检测确认成功后静默关闭本次 GUI，不在普通启动/重新检测时自动关闭。该选择可关闭。失败、取消、超时、旧日志、读取缺项不得触发成功退出。ASUS/MSI 仅服务 Running 不能冒充实体连接，自动退出限定当前技嘉连接证据。
- 低资源策略：GUI 空闲无扫描轮询；仅操作期间更新计时；退出释放托盘、计时器和进程资源。已有明确启用的登录/唤醒维护继续按原约定工作，不因关闭 GUI 擅自删任务；本轮不新增常驻后台进程。
- 设置仅保存本工具的当前用户选项，失败明确提示，不写管理员维护基线；缺失配置采用说明中的默认值，损坏配置明确报错。图标采用简洁几何母版与多尺寸 ICO，避免大型运行时图片依赖。
- 验收：定点合成恢复测试覆盖提前成功、超时、进程变化、旧会话、通信错误；实际控件检查覆盖设置读写/恢复、隐藏入口可恢复、成功/失败退出分支；检查 EXE 图标资源与离屏实际控件，不以此宣称 Windows 任务栏外观或实体连接实机验收完成。
- 实施：先冻结接口与保护条件，再并行连接后端与主代理图标/设置实现；统一本地构建、受影响回归、离屏预览、资源/字节数记录并交付。仍不运行真实服务/驱动启停、提权、安装替换、提交或发布。
- 对抗审查：进程出现/服务运行不等于内存连通；必须要求当前 GCC 会话的完整连接日志且无错误。隐藏任务栏若无替代入口会丢失操作通道，因此仅隐藏时提供托盘；自动退出不能留下本次 GUI 的隐藏常驻。运行时模型正常/重试/回退均为 0 次，无新增第三方依赖。

- 三张预览信息层级/布局有实质差异，中文内容清楚，保留重新检测与详情入口；不虚构硬件控制或图表功能。样图状态仅是设计参考。
- 真实只读检测能完成，输出字段与故障语义不退化；正常、缺组件、读取失败、重复检测保持可解释。
- 用同机器相同入口比较前后耗时及 exe/压缩包体积；数值如实记录，不设无来源的提升比例。若体积/耗时取舍须披露。
- 本地运行现有核心回归及本次必要定点用例；不触发云 CI。
- 不以模拟测试冒充 ASUS/MSI 实体同步、重启、唤醒验证。

## 范围与保护
基线：公开仓库 main / da3da31，使用独立 worktree，分支 codex/mvp-performance-refactor。保留原仓库与用户正在运行的程序。
保留 v0.3.1 的签名校验、指纹校验、操作确认、恢复次数上限与撤销路径。GIGABYTE 按上述后续明确授权恢复手动一次性连接，不恢复旧版持久维护与驱动禁用。
不安装驱动/服务，不改任务计划、控制软件、硬件状态，不运行 enable/repair/restore/watch；不提交、推送、发布或替换已安装程序。不增加网页运行时、第三方 UI 框架或云服务。

## 限制与风险
- Windows / 系统 .NET Framework 编译器；无需下载依赖。GUI 默认禁止抢占输入，使用只读命令行和无前台验证；真实交互未验证须明确。
- 本机真实扫描可能受 WMI、权限与设备状态影响；扫描报告只存忽略目录，不提交机器信息。
- 不能用跨扫描缓存的旧数据掩盖组件改变或故障，安全相关哈希/签名不得为提速跳过。
- 前端已选择方案 3；连接操作延迟与扫描耗时分开验证。发布记录以 GitHub 实查为准。

## 实施计划与针对性审查
先核对基线/打包/调用者 → 测量只读扫描阶段与产物 → 改造已证实热点并添加相关测试 → 集中本地构建/回归/真实扫描对照 → 更新本文证据入口并交付候选。前端并行生成三套方案后等用户选择。
审查结论：不能通过更换重量级桌面技术栈实现“小体积”；不把减行数当性能指标。优先复用系统能力。缓存若影响维护操作安全则不用；确定性工作全部由程序完成。
运行时模型请求：正常 0、重试 0、回退 0，无模型缓存/费用变化。开发期设计生成与代理协作不进入产品运行链。

## 当前事实与待确认项
### 2026-11-14 登录自动连接修复
- 问题：用户报告“不会开机自启动”，代码核对确认 v0.3.2 的技嘉功能仅有手动连接，没有对应登录任务。用户明确选择“自动连接内存，确认成功后静默退出”，替代此前不增加技嘉登录自动连接的限制。
- 交付：设置页增加开启/关闭登录自动连接与真实状态；提供单次后台入口，在当前用户登录后检查已登记的组件基线，健康时退出，未连接时执行一次既有恢复，成功后结束进程；失败保存可查看的结果并非零退出。不新增常驻 watcher、周期重试或唤醒行为，不更改厂商启动设置与其他品牌维护。
- 安全与持久化：显式启用时注册当前用户的任务，固定程序复制到已有受保护安装目录，记录 owner、组件指纹与安装文件身份；任务和配置均核验所有权。禁用只处理自己的任务/状态，拒绝同名外来任务。只有管理员设置动作可以写入，普通读取无需提权。
- 实施计划：先测试登录策略/失败/配置与任务契约 → 后端注册/撤销/单次入口和设置页 → 集中本地验证、实际控件预览与打包 → 检查本机可生效方式。当前助手令牌非管理员，遵守不抢前台规则，不自行弹 UAC；若无法后台完成注册，交付可运行修复并明确仅缺用户在界面点一次启用，不能宣称已生效。
- 验收：合成检查覆盖健康不重启、至多一次恢复、基线漂移/冲突/读取失败退出、注销配置与外来任务保护；构建和设置页实际控件检查通过；只有读回真实任务及配置才标已启用，真实重启登录另列未验证。已通过且未变的连接恢复测试复用，继续采用本地验证，不重复云 CI。
- 对抗审查：Startup 文件夹直接运行需要管理员的连接流程会每次弹 UAC；使用用户一次授权创建的最高权限登录任务。高权限任务不能指向下载目录等用户可替换文件；使用现有管理员保护目录和指纹校验。登录可能与厂商启动竞争，采用原项目已有 25 秒登录延迟，不增加常驻等待。运行时模型请求正常/重试/回退全部为 0。
- 跨账户 UAC 的决定：登记参数绑定发起 GUI 的用户 SID；提权后若身份不同则在任何写入前拒绝。此版支持当前管理员账户的分离令牌提权，不将普通用户通过另一账户提权当作当前用户登记成功。
- 交付沿用用户此前明确的 GitHub 上传要求，发布新的 v0.3.3 预发行，不覆盖 v0.3.2 或合并默认分支。实际本机启用需要一次 UAC，受后台操作规则限制，完成候选后单独询问是否允许弹出；未读回真实任务/配置不得标为生效。验证继续只用本地渠道。
